# M24: النشر على GitHub وCI أخضر

التاريخ: 2026-11-05/06. المستودع: `https://github.com/eom1417/qbank` (خاص). القرارات: DEC-27، DEC-37.

## ما صار

- **المستودع:** `eom1417/qbank` خاص، بكامل التاريخ. المستودع القديم `eom1417/qbank-engine` (مشروع آخر) لم يُلمس.
- **الإيميل المحظور** حُذف من التاريخ قبل النشر: أُعيدت كتابة أول أربعة commits، وحُذفت كل الكائنات القديمة، وتحقّقنا أن لا أثر له في أي كائن. الـcommits الجديدة باسم `eom1417` وإيميل GitHub المخفي.
- **الحماية (DEC-37):** الدمج والرفع العادي لـ`main` بكلمة المالك في المحادثة. الرفع الذي يعيد كتابة التاريخ أو يحذف على GitHub يسأل دائماً، والرفع بالقوة ممنوع. وسُدّت ثغرة قديمة كانت تمرّر الرفع بمرجع يبدأ بـ`+` أو `:`.
- **CI أخضر على GitHub** (قرابة 16 دقيقة): كل الفحوص، و201 اختبار متكامل، و80 اختبار متصفح، وإثبات أن كل فحص يفشل على خطئه المزروع.

## ما أُصلح ليصير CI أخضر

| المشكلة                                                                         | الإصلاح                                                                                         |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| مرآة `.claude/skills` غير موجودة على GitHub (المنصة تصنعها محلياً)              | الـCI يبنيها قبل اختبارات الأداة الذاتية                                                        |
| `CODEOWNERS` بلا مالك                                                           | `@eom1417`                                                                                      |
| لا Node 24 لمضيف الذكاء ولا أدوات القراءة الضوئية في الـCI                      | خطوة تثبّتهما بنفس سكربتات المشروع                                                              |
| اختبار المقارنة يحتاج ملفات المالك الخاصة                                       | يُتجاوز **باسمه** في الـCI فقط (`QBANK_SAMPLES_REQUIRED=false`)، ويبقى إلزامياً على جهاز المالك |
| حزمة الذكاء في `vendor/` لا يمكن إعادة توليدها بأمر                             | أرشيف مثبّت بصمته في ملف القفل، و`vendor-lock.mjs --restore` يعيد بناءها حرفاً بحرف             |
| حارس الفرع الأساسي لا يجد مكتبته (`lizard`) فيتوقف دائماً                       | خلل في أداة الجودة: صار يستعير مكتبة المستودع                                                   |
| اختبار عربي يقرأ «األول»: لا خط عربي على خادم GitHub، فطابعة Chromium تقلب «لا» | تثبيت `fonts-noto-core` في الـCI (أُعيد إنتاج الخطأ محلياً بإخفاء الخط)                         |
| إثبات اختبارات المتصفح تجاوز ساعة (كل رحلة تفشل بانتظار مهلتها)                 | في الـCI يتوقف المتصفح عند أول فشل؛ الإثبات صار 13 ثانية                                        |
| لا مثال خطأ لملفات `.js` لفحصي طول الدوال وتعقيدها                              | مثالان جديدان                                                                                   |
| اختبار ذاتي لشكل جذر الأداة يفشل في المشاريع الحقيقية (DEC-27)                  | يعمل فقط في مستودع الأداة نفسها                                                                 |

## تحديثات المكتبات (Dependabot)

جُمعت الثلاثة في طلب واحد على `main` الجديد: vitest 5.1.0، وlizard 1.25.0 (سطره صُحّح ليقرأه محلل الأداة بتجزئة الحزمة وحدها)، وactions/checkout 7.0.1. نجحت الاختبارات محلياً وأُعيد إثبات فحصي الدوال بالنسخة الجديدة.

## باقٍ

- **حماية الفرع الرئيسي على GitHub** (`genesis.py governance --apply`): تمنع الدمج دون CI أخضر ومراجعة المالك. تغيير إعدادات المستودع يحتاج موافقة المالك الصريحة.
- **`ready=true`** في `engineering.json`: الفحوص كلها صارت مثبتة على GitHub، فيمكن تفعيله بقرار المالك.
- **فرع `m24-github-ci` على GitHub:** حذفه يحتاج موافقة المالك (DEC-37).
- **تكلفة الـCI:** قرابة 16 دقيقة لكل تشغيل. للمستودع الخاص 2000 دقيقة مجانية شهرياً.
- **ملاحظة للمنتج:** ملفات PDF التي تستعمل خطاً عربياً بلا خرائط صحيحة قد تُقرأ «لا» فيها مقلوبة. لم يظهر هذا في ملفات المالك، ويستحق إصلاحاً في القراءة لاحقاً.

# من «يشتغل عندنا» إلى «تجربة نظيفة لخمسة أشخاص» (M25–M29)

طلب المالك (2026-11-06): خطة عميقة لما بقي قبل أن يجرّب QBank أشخاص حقيقيون بشكل نظيف، ثم نأخذ ملاحظاتهم.

## الهدف وتعريف «جاهز للتجربة»

التجربة المحدودة تبدأ حين تتحقق كلها:

1. **التثبيت ينجح من أول مرة** على جهاز نظيف: Windows وmacOS وLinux، بخطوات يفهمها طالب غير تقني، في أقل من 15 دقيقة. ومثبت آلياً في الـCI.
2. **أول دقيقتين تعطي قيمة:** يرى المختبر بنك أسئلة جاهزاً للمذاكرة **قبل** أن يرفع ملفاته، من ملف تجريبي مرفق.
3. **القراءة مقيسة على ملفات متنوعة**، لا على ملفات المالك وحدها، ونسبها معلنة بصدق.
4. **مزوّدان على الأقل مجرّبان حياً:** Claude وChatGPT، مع رسائل واضحة عند انتهاء الاشتراك أو الحد.
5. **التبليغ عن مشكلة بضغطة**، من داخل البرنامج، دون أي محتوى شخصي إلا باختيار المختبر.
6. **إصدار مرقّم** (`v0.1.0`) بملاحظات، وطريقة تحديث مجرّبة لا تمس البيانات.
7. **دليل المختبر** صفحة عربية واحدة: التثبيت، وما يجرّبه، وكيف يبلّغ.

## M25: تثبيت ينجح من أول مرة ✅ (إلا M25.5 اليدوي، التقرير `docs/reports/m25-install.md`)

**لماذا أولاً:** أكبر خطر. ما جُرّب التثبيت إلا داخل حاوية Ubuntu واحدة. المستخدم الذي يفشل تثبيته يترك ولا يعود.

- **M25.1 تثبيت عبر Docker** (قرار المالك، أقترحه المسار الأساسي لـWindows وmacOS): صورة واحدة فيها Node 24 وأدوات القراءة والحزمة. أمر واحد: `docker compose up`، والبيانات في مجلد على الجهاز تبقى بعد التحديث. لا WSL ولا Node ولا Homebrew. ويبقى `install.sh` لمن يريده على Linux أو macOS.
- **M25.2 تثبيت نظيف في الـCI:** وظيفة جديدة تنسخ المستودع على جهاز نظيف (Ubuntu، وmacOS)، وتثبّت من الصفر، وتشغّل البرنامج، وتفتح الصفحة وتتأكد أنها تعمل وأن الاستيراد يقرأ ملفاً. وكذلك صورة Docker تُبنى وتُشغّل وتُفحص في كل تغيير.
- **M25.3 الترقية بلا خسارة:** وظيفة في الـCI: تثبيت الإصدار السابق، ووضع بيانات فيه (بنك، وأسئلة، وجلسة مذاكرة)، ثم التحديث للجديد، والتأكد أن كل شيء باقٍ وأن النسخة الاحتياطية صُنعت قبل الترحيل.
- **M25.4 رسائل الفشل:** كل خطوة تثبيت تفشل تقول بالعربي ماذا ينقص وكيف يُصلح (لا مسار ملف ولا رسالة Node خام). و`install --check` يعطي تقريراً يُنسخ للتبليغ.
- **M25.5 Windows يدوياً:** تجربة واحدة كاملة على جهاز Windows حقيقي (Docker Desktop)، لأن الـCI لا يجرّب Docker Desktop.

**القبول:** وظائف التثبيت النظيف والترقية خضراء في الـCI، وتجربة Windows يدوية ناجحة موثّقة بلقطات.

## M26: القراءة على ملفات غير ملفات المالك ✅ (الملفات الحقيقية المتنوعة من المختبرين، التقرير `docs/reports/m26-reading.md`)

**لماذا:** القراءة قيست على عيّنات المالك فقط. ناقص: كتاب بعمودين، ومسح رديء، وملف مفاتيح منفصل، وأسئلة مقالية (`m18-handoff.md`)، واكتُشف خلل خطوط تقلب «لا» (`m24-github.md`).

- **M26.1 مجموعة مرجعية متنوعة:** 15–20 ملفاً بترخيص يسمح بالاختبار (مواد مفتوحة، أو ملفات يعطيها المختبرون بإذن)، لكل نوع ملفان على الأقل، مع مفتاح إجابات يدوي. تبقى خارج GitHub مثل عيّنات المالك.
- **M26.2 قياس أساس:** نسبة الأسئلة المفصولة صحيحاً، والخيارات، والإجابات، لكل نوع، قبل أي إصلاح.
- **M26.3 إصلاح الأكثر أثراً:** أولها «لا» المقلوبة (تصحيح ثابت في القراءة لخطوط بلا خرائط صحيحة)، ثم الأعمدة، ثم ملف المفاتيح المنفصل.
- **M26.4 الصدق مع المستخدم:** صفحة قراءتها ضعيفة تقول ذلك وتقترح «القراءة بالـAI»، بدل أسئلة مشوهة بصمت.

**القبول:** النسب منشورة في التقرير لكل نوع، ولا نوع تحت حدّ يتفق عليه المالك، و«لا» تُقرأ صحيحة.

## M27: مزوّدو الذكاء الاصطناعي حياً ✅ (إلا تجربة ChatGPT والمفتاح الحية، التقرير `docs/reports/m27-providers.md`)

**لماذا:** Claude وحده جُرّب حياً. ChatGPT لم يسجّل دخوله قط.

- **M27.1 مصفوفة حية:** Claude (اشتراك)، وChatGPT (اشتراك عبر Codex)، ومزوّد بمفتاح API. لكل واحد: تسجيل دخول، واختبار نموذج، واستيراد بحسم الإجابات، وملخص موضوع ببحث.
- **M27.2 المشاكل المتوقعة برسائل واضحة:** نفاد الحد، وانتهاء تسجيل الدخول بعد قرابة 4 أسابيع، ومزوّد غير مثبّت. كل رسالة تقول ماذا حدث وما الخطوة التالية بزر.
- **M27.3 قبل الاستيراد بالـAI:** تقدير صادق للوقت وعدد الطلبات، حتى لا يُفاجأ المختبر بساعة انتظار أو نفاد اشتراكه.

**القبول:** المصفوفة كلها خضراء بتسجيل حقيقي، ورسائل الفشل الثلاث مجرّبة.

## M28: تجربة المرة الأولى ✅ (التقرير `docs/reports/m28-first-run.md`)

- **M28.1 بنك تجريبي مرفق:** ملف أسئلة قصير بترخيص مفتوح، يُستورد من زر «جرّب بنكاً جاهزاً» في أول تشغيل، فيذاكر المختبر خلال دقيقتين قبل أن يحتاج ملفاته أو أي مزوّد.
- **M28.2 «أرسل ملاحظة» من داخل البرنامج:** نموذج قصير (ماذا حاولت، وماذا حدث) يجهّز بلاغاً على GitHub معبّأً مسبقاً، مع تقرير النظام الحالي (أرقام ونسخ فقط). لا يُرفق نص سؤال أو ملف إلا إن اختار المختبر.
- **M28.3 أجهزة متواضعة وكتب كبيرة:** قياس على كتاب 1500 صفحة وعلى جهاز بذاكرة 8GB، وإصلاح ما يبطئ.
- **M28.4 مراجعة النصوص العربية** في كل الشاشات والرسائل، بعين مستخدم لا مطوّر.

**القبول:** مستخدم جديد يصل من التثبيت إلى أول جلسة مذاكرة في أقل من 20 دقيقة دون مساعدة، في تجربة مسجّلة.

## M29: المستودع والإصدار ✅ (إلا الوسم والإصدار على GitHub والحوكمة: بموافقة المالك)

- **M29.1 ملفات المشروع المفتوح:** `SECURITY.md` (التبليغ عن ثغرة)، و`CONTRIBUTING.md`، و`CODE_OF_CONDUCT.md`، وقوالب بلاغات بالعربي والإنجليزي (مشكلة، وقراءة سيئة، وفكرة).
- **M29.2 README يبيع:** عربي وإنجليزي كاملان، ولقطات شاشة، وفيديو قصير لدقيقتين.
- **M29.3 الإصدار:** `CHANGELOG.md`، ووسم `v0.1.0`، وإصدار على GitHub بملاحظاته وصورة Docker مرقّمة.
- **M29.4 الحوكمة:** حماية الفرع الرئيسي، و`ready=true` (بقرار المالك).
- **M29.5 دليل المختبر:** صفحة عربية: التثبيت خطوة بخطوة، وخمس مهام يجرّبها، وكيف يبلّغ، وما لا نجمعه من بياناته.

## التجربة المحدودة

- **من:** 5 أشخاص يختارهم المالك، **بأجهزة مختلفة** (2 Windows، و2 Mac، و1 Linux أو أي)، ومستويات تقنية مختلفة، ومعهم ملفاتهم الحقيقية.
- **الوصول:** المستودع يبقى خاصاً، ويُدعون كمتعاونين للقراءة (يحتاج حساب GitHub لكل واحد)، أو يصير عاماً من البداية (قرار المالك).
- **المدة:** أسبوعان. الأسبوع الأول: التثبيت والبنك التجريبي وملف واحد من ملفاتهم. الثاني: مذاكرة حقيقية ومزوّد ذكاء.
- **المهام:** ثبّت، وذاكر البنك التجريبي، واستورد ملفك، وراجع، واختبر نفسك امتحاناً، واربط مزوّدك واستورد به، وصدّر بنكك واسترده.
- **الملاحظات:** كل بلاغ على GitHub بقالب. فرز مرتين أسبوعياً: **مانع** (لا يستطيع الإكمال) يُصلح خلال يومين، **مزعج** يُصلح قبل الإعلان، **فكرة** تُرتّب لما بعده.
- **شروط الانتقال للإعلان العام:** 4 من 5 ثبّتوا من أول مرة، ولا بلاغ «مانع» مفتوح، وكل واحد أكمل جلسة مذاكرة على ملف حقيقي، ونسب القراءة على ملفاتهم منشورة.

## الترتيب والاعتماديات

## ما يحتاجه المالك

| القرار أو الشيء               | اقتراحي                                                   |
| ----------------------------- | --------------------------------------------------------- |
| Docker مساراً أساسياً للتثبيت | نعم، لـWindows وmacOS، ويبقى `install.sh` بديلاً          |
| مصدر الملفات المتنوعة في M26  | مواد مفتوحة الترخيص + ملفات يعطيها المختبرون بإذن مكتوب   |

| خاص أم عام أثناء التجربة      | خاص بدعوات، والعام عند الإعلان                            |
| اسم الإصدار                   | `v0.1.0`، ثم `v1.0.0` حين يعتمده المالك                   |

## المخاطر

- **Docker Desktop نفسه** قد يكون عائقاً على أجهزة قديمة أو مقيّدة. البديل: `install.sh` على macOS، وWSL على Windows، بدليل مصوّر.
- **تسجيل الدخول لمزوّدي الاشتراك داخل Docker** يمر بالرمز أو الكود الملصق (مجرّب لـClaude وCodex)، لكنه يحتاج تجربة حية داخل الحاوية.
- **الملفات المحمية بحقوق:** لا يدخل GitHub أي ملف أسئلة، ولا البنك التجريبي إلا بترخيص صريح.
- **دقائق الـCI:** وظائف التثبيت على macOS أغلى (عشرة أضعاف دقائق Linux في المستودع الخاص). تُشغّل عند الإصدار وليلياً، لا في كل تغيير.

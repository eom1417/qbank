# M23: قنوات النشر للـagents (DEC-36)

طلب المالك (2026-11-05): agent خارجي (واتساب، تيليجرام، وغيرها) ياخذ من بنك الأسئلة بشكل دوري أسئلة لا تتكرر، يختارها صاحب البنك. الـagent نفسه خارج QBank. وإحصائيات القناة **منفصلة تماماً** عن مذاكرة صاحب البنك، ولكل قناة إحصائياتها.

## الوضع اليوم

- **لا يوجد باب للبرامج الخارجية:** كل `/api` يمر بجلسة المتصفح (`requireActor`). لا مفاتيح API، ولا حد لعدد الطلبات، ولا روابط صور مؤقتة.
- **الأسئلة الجاهزة** (`eligible`) والصور والملخصات لها مالك واحد: `questions`. والمذاكرة والإحصائيات تقرأ وتكتب `study_session` و`study_item` فقط.

## المبدأ: عالمان منفصلان

|                | مذاكرة صاحب البنك                               | القناة                                            |
| -------------- | ----------------------------------------------- | ------------------------------------------------- |
| من يستخدمها    | صاحب البنك في التطبيق                           | agent بمفتاح القناة                               |
| ما تكتبه       | `study_session` و`study_item`                   | `channel`، و`channel_delivery`، و`channel_answer` |
| الإحصائيات     | التحليلات والإتقان والتكرار المتباعد وSmart Mix | شاشة القناة فقط                                   |
| المشترك بينهما | الأسئلة نفسها، تُقرأ ولا تُغيَّر                |                                                   |

- قدرة جديدة `channels` تقرأ الأسئلة عبر واجهة `questions` العامة فقط، ولا تستورد `study` ولا تكتب جداوله. و`study` لا تستورد `channels`. قاعدة في `depcruise` تمنع الاستيراد في الاتجاهين، فيفشل الفحص لو حصل.
- اختبار يثبت الفصل: قناة ترسل دفعات وتستلم إجابات، وأرقام تحليلات صاحب البنك وإتقانه ومواعيد مراجعته لا تتغيّر رقماً واحداً.

## ما يراه صاحب البنك

1. **«قنوات النشر»** في صفحة البنك: اسم القناة، والفصول، وعدد الأسئلة في الدفعة (1 إلى 10)، وما يحدث عند انتهاء الأسئلة (دورة جديدة بترتيب مختلف افتراضياً، أو توقف).
2. **المفتاح يظهر مرة واحدة** عند الإنشاء (`qbc_…`). يُحفظ مجزّأ (SHA-256) مع أول أحرفه للتعرّف عليه. يمكن إيقاف القناة مؤقتاً، أو تجديد المفتاح، أو إلغاؤه، ويسري ذلك فوراً.
3. **إحصائيات كل قناة:** ما أُرسل ومتى، وكم مرة أُرسل كل سؤال، وكم بقي في الدورة. وإن أرسل الـagent الإجابات: نسبة الصواب لكل سؤال، والأكثر خطأً.

## ما يستخدمه الـagent (REST، بالمفتاح في `Authorization: Bearer`)

| الطلب                                                             | ما يفعله                                                                                                                                                          |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/channel/v1/batches` مع `key` اختياري (مثل تاريخ اليوم) | الدفعة التالية: أسئلة لم تُرسل في الدورة الحالية، بنصها وخياراتها وروابط صورها، **بلا الإجابة**. نفس `key` يعيد الدفعة نفسها، فإعادة المحاولة لا ترسل أسئلة جديدة |
| `GET /api/channel/v1/batches/:id/answers`                         | الإجابة والشرح ورابط مختصر من الملخص لكل سؤال في الدفعة، ليرسلها الـagent لاحقاً                                                                                  |
| `POST /api/channel/v1/answers`                                    | إجابة مشترك على سؤال أُرسل (اختياري)، ويعيد صحيحة أم لا. المشترك يُعرَّف برمز يختاره الـagent ويُحفظ مجزّأً، بلا رقم جوال ولا اسم                                 |
| `GET /api/channel/v1/stats`                                       | إحصائيات القناة نفسها                                                                                                                                             |

- **الاختيار:** أسئلة البنك الجاهزة في الفصول المختارة التي لم تُرسل في الدورة، بترتيب عشوائي. ولا يُرسل السؤال نفسه مرتين في الدورة.
- **ما لا يخرج أبداً:** ملاحظات صاحب البنك الخاصة، والأسئلة غير المعتمدة، والمحذوفة أو المخفية، وأي بيانات عن الحساب.
- **الصور:** روابط موقّعة تنتهي بعد 24 ساعة، ولا تعمل إلا لصور الدفعة.

## الأمان

- المفتاح مقصور على قناة واحدة: يقرأ أسئلتها ويسجّل إجاباتها فقط.
- حد لعدد الطلبات لكل مفتاح (ردّ `429`)، وتسجيل آخر استخدام.
- تحقق صارم من كل مدخل. وأخطاء المفتاح تُرد بلا تفاصيل تكشف وجود القناة.
- اختبارات الرفض: مفتاح ملغى، ومفتاح قناة أخرى، وسؤال من بنك آخر، ودفعة قناة أخرى، وتجاوز الحد.

## الوضع المحلي

المنصة المستضافة يصلها أي agent مباشرة. أما النسخة المحلية فتعمل على `127.0.0.1`، فالـagent يصلها إذا كان على الجهاز نفسه، أو عبر نفق يشغّله المالك بنفسه (مثل Cloudflare Tunnel) والجهاز يعمل. يشرح الدليل الطريقتين، ولا يفتح QBank أي منفذ من تلقاء نفسه.

## الخطوات

- **M23.1** النموذج والجداول: `channel`، و`channel_delivery`، و`channel_answer` بمالك وقيود مركّبة (`owner_id`)، وقاعدة `depcruise` للفصل.
- **M23.2** القدرة `channels`: الإنشاء، والمفتاح وتجديده وإلغاؤه، والإيقاف، والاختيار بلا تكرار والدورات، عبر واجهة `questions` العامة.
- **M23.3** باب الـagent: المسارات الأربعة، والتحقق بالمفتاح، وحد الطلبات، وروابط الصور الموقّعة.
- **M23.4** الواجهة: شاشة القنوات، والمفتاح مرة واحدة، والإحصائيات وسجل الإرسال، بالعربي والإنجليزي.
- **M23.5** اختبارات الفصل والرفض والمتصفح.
- **M23.6** MCP: الأدوات نفسها (الدفعة التالية، والإجابات، وتسجيل الإجابة، والإحصائيات) بالمفتاح نفسه، ليستخدمها أي agent يتكلم MCP دون برمجة.
- **M23.7** دليل الربط بأمثلة جاهزة (curl، وn8n، وMCP)، والوضع المحلي، وتقرير المرحلة.

## خريطة الأثر

- **جديد:** `src/server/capabilities/channels/`، و`src/contracts/channels.ts`، و`src/web/capabilities/channels/`، وترحيل واحد، ووحدة حد الطلبات وتوقيع الروابط في `platform/`.
- **يُوسَّع:** واجهة `questions` العامة (قراءة أسئلة جاهزة لبنك وفصول، وصورها)، ومسار الصور ليقبل رابطاً موقّعاً، وصفحة البنك (رابط «قنوات النشر»)، وحذف البنك والحساب (تحذف قنواته)، و`BLUEPRINT.md`.
- **لا يتغيّر:** `study` وجداولها وتحليلاتها، والاستيراد، والمزوّدين.

## معايير القبول

1. agent بمفتاح قناة يستلم يومياً دفعة لا تكرر ما سبق في الدورة، ويستلم إجاباتها لاحقاً.
2. مذاكرة صاحب البنك وإحصائياته لا تتغيّر بأي استخدام للقناة، بإثبات اختبار.
3. كل قناة لها إحصائياتها المستقلة.
4. المفتاح الملغى يتوقف فوراً، ولا يصل أي مفتاح لغير قناته.
5. الفحوص كلها خضراء.

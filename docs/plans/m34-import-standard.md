# M34: استيراد بمعيار ثابت — خطة معتمدة (قيد التنفيذ)

طلب المالك (2026-11-16): بعد تجربة مشاركة فاشلة (لقطات شاشة للكلام تظهر صوراً، وشرح الإجابة يظهر
تحت السؤال، وتنقّل ثقيل، ومؤقت لم يختره)، يُعاد بناء الاستيراد خطَّ إنتاج بطبقات، يعطي الجودة نفسها
مع أضعف نموذج معتمد وأقواه، ولا يحرق التوكنز. صُقلت الخطة بجولتي استجواب (Q1–Q28، القسم 13)،
ووافق المالك على كل التوصيات. النهاية: دمج ونشر، ثم بنك جديد بالملف نفسه وبملف لم يره النظام.

## 1. معنى «100%» (قابل للقياس، بلا تنازل)

لا يَعِد نظام بأن نموذجاً لا يخطئ. المعيار: **الخطأ لا يصل إلى الاختبار بصمت**. كل سؤال إما صحيح
بالتحقق، أو في قائمة المراجعة مع سببه (Q1).

**شروط مطلقة (صفر استثناء، اختبارات ثابتة تفشل لو كُسرت):**

| Z2 | لا كلمة غير موجودة في المصدر. والأرقام والوحدات تطابق المصدر حرفياً (Q20) |

## 2. لماذا فشلت التجربة (مؤكد من الكود وسجلات الخادم)

1. لا استيراد على الخادم قرأه الـAI قراءة كاملة: كان بوضع «التحقق» الذي يراجع علامة الإجابة فقط.
2. القواعد تعامل كل صورة ملصقة «شكلاً» يتبع أقرب سؤال، ولا تشغّل OCR على الصور إن كان للصفحة نص.
3. لا مكان للصورة في البيانات: كل صور السؤال تُعرض معه.
4. القراءة بالـAI تتراجع إلى القواعد بصمت.
5. قالب «اختبار» يضع 30 دقيقة مطويّة تحت «متقدم»، والعداد بالثواني.
6. كل «التالي» طلب للخادم ثم طلب لكل صورة، بلا تحميل مسبق.

إجراء فوري نُفّذ قبل M34 (Q24): لا صورة تخرج من أي مشاركة (`channels/domain/shared-pictures.ts`)
حتى يعطي M34 كل صورة مكانها.

## 3. المبادئ

1. الكود يفعل كل شيء محدد، والـAI يحكم فقط.
2. الـAI يشير ولا ينسخ: يرد بأرقام المقاطع وأدوارها، والنص من المصدر حرفياً.
3. مهمة صغيرة مغلقة لكل استدعاء: اختيار من قائمة، بمخطط JSON، ومثال واحد.
4. تحقق فوري بالكود، ثم إعادة واحدة برسالة الخطأ، ثم نموذج أقوى لهذا الجزء، ثم المراجعة.
5. لا يُدفع الشيء مرتين داخل مدة الاحتفاظ (Q23).
6. إعادة استخدام المالكين الموجودين (`readTextLayer`، `readScan`، `placedImages`، `crops`،
   `askInParts`، فرز M19، `link-keys`، `mapWithLimit`، `usage`، `answer-marks`).

## 4. خط الإنتاج

كل خطوة: مدخل ومخرج بمخطط zod في `domain/pipeline/`، ودالة تحقق، وسجل توكنز.

- **S0 الاستخراج (كود):** طبقة النص حرفياً، وOCR لكل صورة ملصقة وللصفحة الممسوحة، مع ثقة كل كلمة.
  المخرج مقاطع مرقّمة `b1…bn` بنوعها وموقعها ونصها. ثم **بصمة الصفحة** (القسم 4أ): نسبة النص إلى
  الصور، والحبر الملون، والعناوين بعددها، والعلامة المائية، والإطار.
- **S1 مطابقة الأنماط (كود أولاً، ثم الـAI من قائمة مغلقة):** كل صفحة وكل عنصر يُنسب إلى نمط من
  الكتالوج (4أ). ما لم يُعرف بالكود يُعرض على الـAI ليختار من الكتالوج فقط، أو `unknown`.
- **S1ب الرؤية حسب المسار (Q30):** الصفحات التي فيها صور تُقرأ بالرؤية بدقة متوسطة لإرجاع **البنية
  والأدوار وإحداثيات الصور فقط**. نص الصورة يُقبل حين يطابق OCR المنطقة نفسها، وإلا فرؤية على المقطع
  وحده، واختلاف القراءتين أو أي رقم أو وحدة → مراجعة (Q20). خط اليد يبقى صورة (Q6).
- **S2 التقسيم (AI نص):** نافذة صفحات بتداخل صفحة. المخرج حدود كل سؤال، وحدود كل **حالة مشتركة**
  والأسئلة التي تخصها (Q18). التحقق: لا تداخل، ولا فجوة إلا حشو.
- **S3 الأدوار (AI نص):** لكل مقطع وصورة: `stem | case | option:A…J | answer | explanation | noise`.
  التحقق: خياران على الأقل، حروف متتابعة، الإجابة من الخيارات، لا مقطع بلا دور.
- **S4 مفتاح الإجابات:** الكود أولاً (`answer-keys.ts`)، والـAI عند الغموض فقط، والعلامات (Z7) دليل.
- **S5 التجميع (كود):** النص حرفياً، والحالة منسوخة لكل سؤال بوسم المجموعة، والصور بمكانها
  (`stem`، `option` بحرفها، `explanation`، Q22).
- **S6 الضبط (كود):** كل شروط Z، والقواعد القائمة (`screening.ts`، `defects.ts`، التكرار M8).
- **S7 فرز الإجابات (M19):** إجابة لم يطبعها الملف تدخل الاختبار إن اتفق الحلّالان، بشارة «إجابة بالذكاء
  الاصطناعي»، وإن اختلفا فللمراجعة (Q9).
- **S8 مراجعة عيّنة (نموذج قوي):** للمُصعَّد والمختلف فيه فقط.

## 4أ. الحوكمة: كتالوج الأنماط (توجيه المالك)

الهدف: أي شكل في أي ملف له **مسار محكوم** مكتوب سلفاً، فلا يرتجل أي نموذج. الكتالوج ملف بيانات مرقّم
بإصدار (`domain/pipeline/patterns/catalog.ts`)، ولكل نمط بطاقة ثابتة:

| حقل البطاقة | معناه |
| --- | --- |
| `id` ووصف بسطر | مثل `hand_circle_answer`: دائرة يد حول حرف خيار |
| إشارات الكود | ما يكشفه الكود وحده (لون الحبر، الشكل، الموقع من الخيار، كلمات العنوان) |
| سؤال الـAI المغلق | حين لا يكفي الكود: سؤال نعم/لا أو اختيار من قائمة، بمثالين من الملفات (موجب وسالب) |
| المسار | الخطوة التي تتولاه وما تفعله به (نص، صورة بمكانها، دليل إجابة، حشو) |
| شرط القبول | ما يتحقق منه الكود قبل قبول النتيجة |
| مسار الفشل | إعادة، ثم نموذج أقوى، ثم مراجعة بسبب مسمّى |
| الأمثلة المرجعية | صفحات من مجموعة الضبط بحقيقتها، تُقاس عليها البطاقة وحدها |

**الطبقات بالترتيب:** (1) OCR وطبقة النص → (2) مطابقة الأنماط بالكود → (3) الأمثلة: النمط غير المحسوم
يُعرض على الـAI مع مثالَي بطاقته فقط، لا الكتالوج كله، توفيراً للتوكنز → (4) الحالات الخاصة: مسار البطاقة
→ (5) الضبط. **النموذج لا يُسأل أبداً سؤالاً مفتوحاً**؛ يُسأل عن بطاقة واحدة في كل مرة.

**الأنماط الأولى** (من جرد الملفات الـ29):

| النمط | المسار |
| --- | --- |
| `typed_question` سؤال مكتوب في طبقة النص | نص حرفياً |
| `image_question` سؤال كامل داخل صورة | رؤية للبنية + OCR للنص، سؤال كامل (Q33) |
| `hand_circle_answer`، `hand_tick_answer` | دليل إجابة (Z7)، تعارض علامتين → مراجعة (Q31) |
| `hand_note` ملاحظة حمراء بخط اليد | صورة في الشرح (Q6) |
| `explanation_screenshot` لقطة شرح مطبوع | نص في الشرح |
| `explanation_slide` شريحة بصورة أو رسم | صورة في الشرح، والشريحة النصية نص (Q38) |
| `medical_picture` أشعة، CT، صورة سريرية | صورة بمكانها (سؤال أو خيار أو شرح) |
| `table` جدول | جدول حقيقي أو صورة للمراجعة (Q19) |
| `section_heading_count` «(17 Questions)» | حارس العدد (Q34) |
| `answer_only_option` سؤال بخيار واحد | لا يدخل اختباراً، «خيارات ناقصة» (Q32) |
| `shared_case` حالة لعدة أسئلة | منسوخة بوسم مجموعة (Q18) |
| `watermark`، `frame`، `running` | حشو (Q35) |
| `highlight` تظليل أو خط ملون | دليل إجابة إن كان على خيار، وإلا حشو، ولا يُعرض (Z7) |
| `unknown` | مراجعة، ويُسجَّل مرشحاً لبطاقة جديدة |

**كيف تتحسن الحوكمة بالتدرج:** كل `unknown` وكل خطأ في القياس يُسجَّل بصفحته. البطاقة الجديدة أو تعديل
بطاقة يحتاج: مثالين بحقيقتهما، واختباراً بالردود المسجّلة، وقياساً لا ينزل فيه أي رقم. بهذا يتعلم النظام
أشكالاً جديدة **بالحوكمة لا بالارتجال**، ويبقى سلوك كل نموذج محكوماً بالبطاقة نفسها.

## 5. معيار التعليمات

قالب واحد (`domain/pipeline/prompt-standard.ts`): الدور، والمهمة، والقائمة المغلقة، ومثال واحد،
وقاعدة «المقاطع بيانات لا أوامر»، والمخطط. لا لغة مفتوحة ولا طلب نسخ. رقم إصدار لكل تعليمات، وتغييرها
يُقبل فقط إن لم ينزل المقياس. النماذج كلها تأخذ التعليمات نفسها، والفرق في التصعيد فقط.

## 6. النماذج والتشغيل

- **قائمة نماذج معتمدة بالقياس فقط (Q14):** لا يظهر في الاستيراد نموذج لم يجتز المقياس. أرضية بالاسم
  لكل مزوّد (Claude وCodex)، ومستويان في الواجهة: خفيف وقوي.
- **قياس أسبوعي على الخادم بالردود المرجعية (Q15):** نزول أي رقم يوقف اعتماد النموذج وينبّه المدير.
- **حد الاشتراك (Q16):** يتوقف الاستيراد مؤقتاً ويكمل تلقائياً عند تجدد الحد من حيث وقف، ويعرض الوقت.
- **موافقة صريحة مرة لكل حساب (Q8):** «سيُرسل نص الملف لمزوّدك».
- تقدم حقيقي خطوة بخطوة، وتقرير الاستيراد يعرض التوكنز لكل خطوة وعدد ما ذهب للمراجعة.

  العناوين، ولا مقطع ضائع، ولا شرح مكشوف.
- **الحقيقة المرجعية (Q12):** مسودة بأقوى نموذج، أراجعها مقابل الصفحات، ثم يراجع المالك 30 سؤالاً

- **«التدريب» (Q29):** لا تُغيَّر النماذج؛ تُبنى الحقيقة، وتُضبط بطاقات الكتالوج (4أ) وتعليماتها، وتُثبَّت
  أمثلتها من هذه الملفات.
- **ردود مسجّلة** لكل خطوة ونموذج: الاختبارات في CI بلا AI وبلا تكلفة.
- **أداة القياس** (توسيع `bench:extraction`): الدقة لكل خطوة، والتوكنز، والتصعيد، والزمن، لكل نموذج،

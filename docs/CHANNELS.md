# ربط agent بمشاركة

منذ M30 (DEC-39) كل طريقة تخرج بها أسئلة بنكك «مشاركة» في شاشة **«المشاركات»**: مشاركة لـagent (قنوات النشر السابقة، وهي هذا الدليل)، أو رابط اختبار، أو رابط تمرين. ولكل مشاركة سياسة واحدة يطبّقها الخادم على كل طريق، وسجل لا يُمحى، وبطاقة بلغة واضحة. التفصيل: `docs/plans/m30-governed-sharing.md`. **واجهة الـagent أدناه لم تتغيّر**، والقناة المنشأة قبل M30 تعمل كما كانت.

مشاركة الـagent تعطي agent خارجياً (واتساب، تيليجرام، n8n، Make، أو أي agent ذكاء اصطناعي) أسئلة من بنكك على دفعات لا تتكرر. الـagent نفسه خارج QBank: هو يرسل الرسائل ويحدد المواعيد، وQBank يعطيه الأسئلة فقط.

## 1. أنشئ المشاركة

من صفحة البنك ← **المشاركات** ← مشاركة جديدة، واختر قالب **«API/MCP»** أو **«سؤال يومي لواتساب أو تيليجرام»**:

- **الاسم**، و**الفصول** (بلا اختيار: البنك كله)، و**عدد الأسئلة في الدفعة** (1 إلى 10).
- **عند إرسال كل الأسئلة:** ابدأ من جديد بترتيب مختلف، أو توقف.

يظهر **مفتاح القناة** (`qbc_…`) مرة واحدة فقط. انسخه وأعطه للـagent. من يملكه يأخذ أسئلة هذه القناة فقط، لا شيء غيرها. ومن نفس الشاشة: أوقفها مؤقتاً، أو أنشئ مفتاحاً جديداً (القديم يتوقف فوراً)، أو احذفها، أو اعرض أرقامها.

وتضيف السياسة ما لم يكن في القنوات قبل M30، وكله اختياري: تاريخ بداية ونهاية، وحد للدفعات في اليوم، ووقت كشف الإجابات (فوراً، أو بعد ساعات، أو بعد انتهاء المشاركة). وأسئلة أي اختبار لم يُؤرشف **محجوزة** عن مشاركات الـagent افتراضياً.

**إحصائيات القناة منفصلة تماماً عن مذاكرتك:** ما ترسله القناة وما يجيب به المشتركون لا يغيّر تحليلاتك ولا إتقانك ولا مراجعتك المتباعدة.

## 2. واجهة الـagent (REST)

كل طلب يحمل المفتاح: `Authorization: Bearer qbc_…`. الحد 120 طلباً في الدقيقة لكل قناة.

| الطلب                                                                                      | ما يفعله                                                                                                        |
| ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `POST /api/channel/v1/batches` مع `{"key": "2026-11-05"}`                                  | الدفعة التالية: أسئلة لم تُرسل في هذه الدورة، **بلا إجاباتها**. نفس `key` يعيد نفس الدفعة، فإعادة المحاولة آمنة |
| `GET /api/channel/v1/batches/<id>/answers`                                                 | الإجابات والشرح، وموضوع السؤال وفكرته من ملخص AI إن وُجد، لترسلها لاحقاً                                        |
| `POST /api/channel/v1/answers` مع `{"deliveryId": "…", "recipient": "…", "choice": ["B"]}` | إجابة مشترك (اختياري): يرد بصحيحة أم لا. `recipient` اسمك أنت له، ويُحفظ مجزّأً لا كما هو. لا ترسل رقم جوال     |
| `GET /api/channel/v1/stats`                                                                | أرقام القناة                                                                                                    |
| `GET /api/channel/v1/pictures/<id>`                                                        | صورة سؤال أرسلته القناة (روابطها في `pictures` داخل الدفعة)                                                     |

**ردّان جديدان ممكنان منذ M30** (يحددهما ما اخترته في السياسة؛ بغيرهما لا يتغيّر شيء):

- `not_revealed_yet` من `/answers`: لم يحن وقت كشف إجابات هذه الدفعة بعد. أعد الطلب لاحقاً.
- `share_limit_reached` (`429`) من `/batches`: بلغت المشاركة حد دفعاتها اليوم (بتوقيت UTC).

وكذلك `share_not_started` قبل تاريخ البداية، و`share_ended` بعد النهاية.

مثال:

```bash
KEY=qbc_...
curl -X POST https://<عنوان QBank>/api/channel/v1/batches \
  -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"key": "2026-11-05"}'
```

**n8n / Make:** عقدة HTTP Request بالطريقة `POST` على العنوان أعلاه، وترويسة `Authorization`، ثم أرسل `questions` لواتساب أو تيليجرام. وبعد ساعات عقدة ثانية تطلب `/answers` للدفعة نفسها.

## 3. عبر MCP (لـagents الذكاء الاصطناعي)

العنوان `https://<عنوان QBank>/api/channel/v1/mcp` (Streamable HTTP) بنفس المفتاح في `Authorization`. الأدوات: `next_batch`، و`batch_answers`، و`record_answer`، و`channel_stats`.

مثال إعداد لـagent يدعم MCP عبر HTTP:

```json
{
  "mcpServers": {
    "qbank": {
      "type": "http",
      "url": "https://<عنوان QBank>/api/channel/v1/mcp",
      "headers": { "Authorization": "Bearer qbc_..." }
    }
  }
}
```

## 4. إن كان QBank على جهازك

النسخة المحلية تعمل على `127.0.0.1`، فلا يصلها agent في السحابة. إما أن يعمل الـagent على الجهاز نفسه، أو تفتح أنت نفقاً (مثل Cloudflare Tunnel) والجهاز يعمل وقت الإرسال. QBank لا يفتح أي منفذ من تلقاء نفسه. على النسخة المستضافة يصل أي agent مباشرة.
